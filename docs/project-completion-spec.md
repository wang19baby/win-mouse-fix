## 必须保持的约束

- 默认不启用 LAN、指针加速或硬件 DPI 写入；不改用户现有 `config.toml` 的选择。
- 不记录/发布 token、原始输入、窗口缩略图或用户凭据。
- 不丢弃、提交或清理已有用户工作；保留 Windows 原生输入失效回退。
- 不增加兼容别名、假成功回退或仅用于绕过门禁的测试。
- 自动化验证不替代实际鼠标、Logitech 设备、iOS/Android、UIPI/防火墙和混合 DPI 显示器验收。

## 修订

- 初版：以当前代码为基线，旧优化证据只作为历史记录；离线 PWA 的安全上下文和硬件 DPI 写入单列外部验收边界。
- 修订 2026-10-14：指针加速选择**原生移动透传 + 有界异步补偿增量**，不吞掉真实移动后异步重放。`WH_MOUSE_LL` 的 `pt` 是系统处理后的屏幕坐标，非 Raw Input；仅能保证观察到的原生移动增益，不能宣称硬件原始位移、跨设备一致的手速曲线。限定放大系数 >=1；额外增量失败时原生输入不受影响。所有注入/外部移动重设基准，在线切换停止旧工作线程。
- 修订 2026-10-14：Win32 `SendInput` 可以等待本线程的低级钩子回调，因此配置切换的消息线程不能同步 join 正在注入的工作者，否则有死锁风险。禁用时先失效 generation 并丢弃容量为 1 的队列、让线程自行退出；已经进入 `SendInput` 的单次注入可能在禁用返回后抵达，真实鼠标/UIPI 场景需人工验证。不得宣称同步零残留或原始设备加速。
- 修订 2026-10-19：为可复现 W2 验收新增 `[remote].local_only`（默认 false）。true 时仅绑定 loopback、跳过防火墙；E2E 在独立临时目录运行真实 exe、动态端口和新 token，不复用/终止用户实例。
- 修订 2026-10-19：录制入口改为“保存并录制”，先校验并持久化草稿，失败保留窗口。配置已保存但运行时启用失败与未保存分开提示；安装就绪状态独立于配置相等性，同配置/同前台应用在安装失败后仍可重试。

## 远程拖选生命周期保障（2026-10-19）

Tier 3：全局输入状态、网络失联、并发会话与退出排序。自主执行，本修订未取得独立的实施前规格批准。

### 方案与设置

- 复用当前功能分支，保留现有工作树；不提交、不回滚用户修改。不安装软件、不新增依赖。
- 单个容量受限的远程输入工作者拥有所有远程注入及左键状态；UI/钩子线程不等待持有 SendInput 的锁。
- 新文件：`src/remote_input.rs`、`assets/drag.js`、`tests/e2e/drag.spec.js`；复用现有 Rust/Playwright 验证。受控原生烟测及门禁入口放在 `tools/drag_smoke.py` / `tools/drag-gauntlet.ps1`。
- 干净协议切换：`{t:"drag", action:"start|renew|end", id:正的安全整数}`；拖动 move 携带 `drag_id`。旧 longpress gesture 按下/释放入口删除，不保留无会话所有权旁路。
- 每个认证连接独立会话，拖拽 id 单调增长；每 250ms 续期，2s 未续期回收。续期、结束及断线取消不依赖普通移动队列容量。
- 注入完成后才回执 started；失败释放保留债务并重试，不伪报 ended、不让新按下覆盖。正常服务停止非阻塞；进程退出先卸载钩子，再等待输入工作者完成释放。

### 验收与失败模型

| ID | 输入/异常 | 必须观察到的结果 |
|---|---|---|
| R1 | 正常 start → 带 id 移动 → end | 一次左键按下、拖动、一次释放；能够在自有文本窗口形成选择；状态回执对应真实成功 |
| R2 | 重复 start / 重复 end | 不重复注入；结束的 id 不能重新按下 |
| R3 | 旧 id 或另一会话的 renew/end/move | 不续期、不释放、不移动当前拖拽；并发请求不抢占 |
| R4 | 物理左键已按下，或按下注入失败 | 拒绝远程按下；不取得所有权、不发送补偿释放破坏已有按键状态 |
| R5 | 触摸取消、丢失 capture、第二根手指、blur、pagehide、hidden、WS close | 清计时器、触点和待发送移动，不生成额外 tap；可发送时立即 end，否则服务端回收 |
| R6 | 无心跳、断开 TCP、未完成的 WebSocket 帧 | 独立看门狗约 2s 内开始释放，不依赖 socket 的 30s 探测 |
| R7 | 普通输入队列满，end/取消同时到来 | 释放不会被队列丢弃；过期/取消的排队 start 不会迟到按下 |
| R8 | 左键释放或拖动 SendInput 被拒绝 | 进入释放债务，阻止后续远程输入；重试成功后才清所有权；给出错误而非假成功 |
| R9 | 服务停止/重启，按下注入正在进行 | stop 不在 UI 线程等锁；任何已成功 down 最终由同一工作者依次 up，旧会话不能控制新会话 |
| R10 | 正常进程退出 | 先禁入/取消，再卸载本进程钩子，最后等待释放；没有 writer-lock/SendInput 的循环等待 |
| R11 | 两个触控页面 | 使用同一生命周期 helper；实际页面验证取消和恢复、无额外点击、最新 SW 缓存包含必要脚本 |
| R12 | 不变量 | 不记录 token/原始输入，不改变认证/防火墙默认值，不抑制物理钩子事件，不创建每事件线程；完整门禁仍通过 |

边界：UIPI/安全桌面可能拒绝注入；持续拒绝释放时不能宣称已松开，正常退出选择等待而不是丢弃债务。强杀进程、系统崩溃及物理左键在检查之后的并发变化不能由软件保证消除；真实硬件和手机兼容性仍单独验收。
